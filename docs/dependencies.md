# Dependencies

This page covers how alfred's Python dependencies are declared, locked and
installed, and why the unusual pins are there. `pyproject.toml` keeps its
comments to a line and points here.

## Lockfiles

| File | Holds | Made with |
|---|---|---|
| `pdm.lock` | the application: groups `default`, `dev`, `render`, `test` | `pdm lock -G dev -G render -G test` |
| `pdm.docs.lock` | the docs tools: group `docs` only | `pdm lock -L pdm.docs.lock -G docs --no-default` |
| `requirements.lock` | `default`, exported from `pdm.lock` | the command in its header |
| `requirements-test.lock` | `test`, exported from `pdm.lock` | the command in its header |
| `requirements-render.lock` | `render` (otto's render extra), exported from `pdm.lock` | the command in its header |

The image, nox (`tests/noxfile.py`) and CI install the three exports with
`--no-deps`. Then they install otto, vox and alfred editable, also with
`--no-deps`, so nothing is resolved on the day of a build. pdm honours
`pyproject.toml`'s overrides and pip has no such thing, so a resolving install
of these files fails with `ResolutionImpossible`.

`tests/unit/test_stack_config.py` holds each export to `pdm.lock`: the same
versions and the same markers.

To change a dependency:

1. Relock with pdm 2.29 or later. A bare `pdm lock` or `pdm update <pkg>`
   relocks only the groups `pdm.lock` already holds.
2. Re-export each `requirements*.lock` with the command in its header. pdm
   writes everything from its own `# This file is @generated by PDM.` line
   down; keep the hand-written header above that line.

pdm 2.22 could not work with the python-multipart override in the lock. `pdm
add`, `pdm update <pkg>` and `pdm lock --update-reuse` failed with
`CandidateNotFound` for python-multipart, and a full `pdm lock` had not
finished after 49 minutes. pdm 2.29 relocks everything in under two minutes.

### The docs tools have a lock of their own

A lockfile records one marker per package, shared by every group it holds.
mkdocs-material needs colorama on every platform. The application needs it
only on Windows, through pytest and tqdm. While `pdm.lock` held the docs group
too, its colorama had no marker, and the next export would have installed
colorama in the Linux image. Locked apart, `pdm.lock` keeps colorama's
`sys_platform == "win32" or platform_system == "Windows"`.

`tests/unit/test_docs_site.py` checks three things:

- `pdm.lock` holds no docs group;
- `pdm.docs.lock` holds the docs group and nothing else;
- `./al prod` builds the site with `squidfunk/mkdocs-material` at the release
  `pdm.docs.lock` holds.

The docs group's ranges are the ones `.github/workflows/docs.yml` installs.
They stay below MkDocs 2, which Material for MkDocs does not run on.

## Overrides

An override in `[tool.pdm.resolution.overrides]` replaces every requirement on
a package, its dependents' included. Only pdm reads them, which is why every
install uses `--no-deps` (above).

- **python-multipart `>=0.0.31`.** fastapi-users 10.4 pins 0.0.6, which has
  nine advisories against it, CVE-2024-24762 and CVE-2024-53981 among them.
  Every fastapi-users before 15.0.4 pins an exact release with some still open
  (14.x pins 0.0.20, which has seven), and 15 cannot run here (below). 0.0.31
  is the first release with none open. fastapi-users never imports it; FastAPI
  and Starlette do, and both take it. alfred also declares it directly,
  although nothing in alfred imports it. It parses every form the api takes,
  the login form anyone can post included, so alfred depends on its fixes.
- **al-otto from the submodule.** Every install path runs the engine at
  `alfred/otto`, so pdm locks it from there. Resolved from PyPI, the lock
  described al-otto 0.2.2 as published. That release is older than the
  submodule, and its render extra still names bezier, which has no wheel for
  this Python. pip ignores `tool.pdm`, and a published wheel cannot name a
  path, so the metadata names al-otto by version. When otto publishes its
  next release, raise both floors, in `dependencies` and in `render`. The
  override stays.

## Pins

### fastapi-users 10.4

alfred carries copies of five fastapi-users methods that hash in the thread
pool, and the api refuses to start on any release but 10.4.2. See [password
hashing](api/auth.md#password-hashing).

fastapi-users 15 cannot run here yet. 15.0.0 removed its pydantic 1 support,
and otto pins `pydantic~=1.10`. 15.x declares no bound on pydantic, so a
resolver installs it beside 1.10 without complaint. On pydantic 1.10.26,
though, the library's own register, login and `/users/me` routes answer 500.
Its models call `model_dump()` and `model_validate()`, which are pydantic 2
methods. 14.0.2 is the newest release that runs on pydantic 1.10.

GHSA-5j53-63w8-8625 (CVE-2025-68481), fixed in 15.0.2, is a CSRF in the OAuth
router's state. alfred mounts no OAuth router;
`test_what_is_not_replaced_cannot_be_reached` in
`tests/unit/test_password_hashing.py` fails if one appears.

### passlib, and setuptools below 81

fastapi-users 10.4 hashes with passlib. `passlib.pwd` imports `pkg_resources`
at module scope, and setuptools 81 removed `pkg_resources`. Without the cap,
every module that touches authentication raises `ImportError` on a clean
install. That showed up as ten unrelated test modules failing to collect, and
the errors named neither passlib nor setuptools. The `test` extra repeats the
cap, because the test environment installs its own setuptools.

The cap only buys time. passlib's last release was in 2020. The way out is
fastapi-users 13 or later, which hashes with pwdlib instead. That comes with
the fastapi-users upgrade.

### Pillow 12.3, below 13

moviepy 1.0.3 resizes with `Image.ANTIALIAS`, which Pillow 10 removed. Pillow
was therefore held at 9.5, which has advisories against it, CVE-2023-4863 and
CVE-2024-28219 among them. otto now restores the name when Pillow lacks it
(`alfred/otto/otto/__init__.py`), and `tests/pipeline/test_resize.py` draws
and encodes through that path. 12.3 has no advisory open. It stays below 13
until 13 has had the same test.

### numpy, below 2

This is a constraint more than a dependency. Nothing in alfred imports numpy;
moviepy and otto do, and neither bounds it. 1.26 is the last 1.x. It stays
below 2, which removed APIs, until the encode path (moviepy 1.0.3) has run on
2.x in the image.

### httpx

This is vox's client. vox installs with `--no-deps`, so alfred declares what
vox's core imports, and httpx is all of it. vox's other dependencies (a speech
synthesizer, a CLI) serve parts alfred does not load. The floor is vox's.

### Python 3.11 only

The image, CI, ruff and black all target 3.11. otto caps Python below 3.12:
its `pydantic~=1.10` admits releases whose newest supported Python is 3.11.
pdm locks for the whole `requires-python` range. With a floor of 3.8, any
package that had since dropped 3.8 stayed at its last release for 3.8, numpy
1.24 and anyio 4.5 among them, whatever Python ran.

## What the checks are told

`pyproject.toml`'s tool tables:

- **black** runs with `-S`, which keeps single quotes. Its target is pinned to
  py311; otherwise black infers one from the syntax it sees, and warns that
  the running interpreter cannot verify its own output. It uses
  `force-exclude` rather than `exclude`, because black ignores `exclude` for
  paths named on the command line. The submodules and `website/` have their
  own gates.
- **ruff** checks its defaults (`E4`, `E7`, `E9`, `F`) plus import order (`I`)
  and bugbear (`B`): rules that catch mistakes rather than express taste.
  Layout belongs to black. With no rule set given, ruff's implicit one
  reported 157 findings, most of them stylistic, and a usage error, so nobody
  read its output.
    - `tests/conftest.py` may import below code (`E402`), because the
      environment has to be set before the app's imports read it.
    - Bugbear treats FastAPI's `Depends()`, `Query()` and the rest as
      immutable. A dependency declared as a default argument is FastAPI's
      documented spelling, and evaluating it once is intended.
- **pytest** makes `xfail` strict. An xfail pins a known defect, so the test
  fails once the defect is fixed, and the marker has to come off.
