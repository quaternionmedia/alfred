# Dependencies

This page covers how alfred's Python dependencies are declared, locked and
installed, and why the unusual pins are there. `pyproject.toml` keeps its
comments to a line and points here.

## Lockfiles

| File | Holds | Made with |
|---|---|---|
| `pdm.lock` | the application: groups `default`, `dev`, `render`, `test` | `pdm lock -G dev -G render -G test` |
| `pdm.docs.lock` | the docs tools: group `docs` only | `pdm lock -L pdm.docs.lock -G docs --no-default` |
| `requirements.lock` | `default`, exported from `pdm.lock` | the command in its header |
| `requirements-test.lock` | `test`, exported from `pdm.lock` | the command in its header |
| `requirements-render.lock` | `render` (otto's render extra), exported from `pdm.lock` | the command in its header |

The image, nox (`tests/noxfile.py`) and CI install the three exports with
`--no-deps`. Then they install otto, vox and alfred editable, also with
`--no-deps`, so nothing is resolved on the day of a build. pdm honours
`pyproject.toml`'s overrides and pip has no such thing, so a resolving install
of these files fails with `ResolutionImpossible`.

`tests/unit/test_stack_config.py` holds each export to `pdm.lock`: the same
versions and the same markers.

To change a dependency:

1. Relock with pdm 2.29 or later. A bare `pdm lock` or `pdm update <pkg>`
   relocks only the groups `pdm.lock` already holds.
2. Re-export each `requirements*.lock` with the command in its header. pdm
   writes everything from its own `# This file is @generated by PDM.` line
   down; keep the hand-written header above that line.

### The docs tools have a lock of their own

A lockfile records one marker per package, shared by every group it holds.
mkdocs-material needs colorama on every platform. The application needs it
only on Windows, through pytest and tqdm. While `pdm.lock` held the docs group
too, its colorama had no marker, and the next export would have installed
colorama in the Linux image. Locked apart, `pdm.lock` keeps colorama's
`sys_platform == "win32" or platform_system == "Windows"`.

`tests/unit/test_docs_site.py` checks three things:

- `pdm.lock` holds no docs group;
- `pdm.docs.lock` holds the docs group and nothing else;
- `./al prod` builds the site with `squidfunk/mkdocs-material` at the release
  `pdm.docs.lock` holds.

The docs group's ranges are the ones `.github/workflows/docs.yml` installs.
They stay below MkDocs 2, which Material for MkDocs does not run on.
